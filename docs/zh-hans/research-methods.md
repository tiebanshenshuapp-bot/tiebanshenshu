# 研究方法 / Research Methods

> 本文说明本项目**如何判断、如何引用、如何处理争议**。
> 如果你要评估我们是否可信，请读这一页。

---

## 一、核心原则：三条硬规矩

### 规矩 1：区分史料层级

任何说法都必须归入下面某一层，并在文中标出：

| 层级 | 判据 | 处理方式 |
|---|---|---|
| **古籍原文** | 能在清代及以前刊本中查到 | 引用并注版本、卷次、页码 |
| **传统说法** | 师传、流派自述、民间传闻，无一手史料 | 明确标注「传统说法」，**不得表述为史实** |
| **学术讨论** | 有文献学研究支持，存在争议 | 给出出处，**允许多说并存** |
| **编者观点** | 本项目的整理、推论、解释 | 标明是本项目观点 |
| **虚构样例** | 为演示格式而造 | **显著标注「虚构」** |

**为什么这条最重要？**

因为术数研究最大的问题不是"说错"，而是**把"听说"当成"记载"**。
一旦层级混了，整篇文章就不可信了。

---

### 规矩 2：不宣称正统

我们不使用以下表述，除非有硬证据（目前没有）：

| 禁止表述 | 原因 |
|---|---|
| 「唯一正宗」 | 传承谱系缺失，无人能证明 |
| 「邵雍亲传」 | 明代已被杨慎质疑，宋代无记载 |
| 「帝王秘传」 | 无任何史料 |
| 「香港是真正发源地」 | 香港是传播重镇，非起源地 |
| 「我们的算法最准确」 | 无法用可复现方法验证 |

**替代写法**：

> ❌ 「铁板神数是邵雍亲传的帝王秘术」
>
> ✅ 「传统上将铁板神数托名邵雍，但这一说法缺乏宋代文献支持，
>     明代杨慎已明确批评此类托名」

---

### 规矩 3：不做命运断言

本项目讨论**文献与文化**，不提供预测服务。

具体禁止：

- ❌ 「你的命如何如何」
- ❌ 「这个条文说明你会……」
- ❌ 「准确率 XX%」
- ❌ 「改命」「转运」「化解」
- ❌ 任何医疗、投资、法律建议

**我们做的是**：解释术语、梳理源流、提供可运行的基础换算工具。

## 二、引用规范

### 公版古籍的引用格式

```text
作者. 书名[M]. 朝代. 版本信息. 卷次: 页码.

示例：
邵雍. 皇极经世[M]. 宋. 清乾隆XX年刊本(或：XX出版社19XX年影印本). 卷X: 第XX页.
```

**硬要求**：

1. **必须写版本** —— "据古籍记载"不算引用
2. **尽量写页码** —— 没有页码时说明原因（如影印本无连续页码）
3. **区分原文与转引** —— 如果是从二手著作转引，必须写明"转引自"

### 为什么版本这么重要

因为**同一部书的不同版本，内容可能不同**。

铁板神数尤其如此：

- 抄本之间文字有出入
- 不同"校订者"做了不同修改
- 现代影印本可能选自不同底本

**不写版本，等于没写来源。**

## 三、如何处理争议

### 我们的做法

遇到争议时，我们**不选边，而是呈现争议结构**：

```markdown
关于 X，存在两种说法：

**说法 A**（支持者：……）
论据：……
来源：……

**说法 B**（支持者：……）
论据：……
来源：……

**我们的判断**：倾向 A / 倾向 B / 暂不判断
理由：……
```

### 什么时候我们会选边

只有当**证据明显不对等**时。例如：

| 争议 | 我们的立场 | 理由 |
|---|---|---|
| 是否邵雍所作 | 倾向"不是" | 宋代无记载 + 明代已有明确批评 |
| 「铁卜子」是否真有其人 | 倾向于存疑 | 同时代文献完全无痕迹 |
| 各本条文哪本更可靠 | **不判断** | 缺乏校勘研究，无法判断 |
| 一万二千条的确切数目 | **不判断** | 各本不同，无权威统计 |

## 四、公开内容的筛选标准

本仓库公开内容，必须满足：

### 4.1 权利状态清楚

| 类别 | 可否公开 |
|---|---|
| A. 明确公版（清代及以前原文） | ✅ |
| B. 本项目原创且有权公开 | ✅ |
| C. 有明确授权可引用的第三方 | ✅ 有限引用 |
| D. 权利状态不明 | ❌ |
| E. 商业私有资产 | ❌ |
| F. 个人隐私 / 密钥 | ❌ |

### 4.2 有可核查来源

无法追溯来源的内容，一律不公开。

### 4.3 有研究或教学价值

不为了"凑数"发布内容。宁可少，不可滥。

## 五、我们不做什么研究

明确排除，避免误解：

| 不做的 | 原因 |
|---|---|
| 用统计方法"验证"命理准确性 | 涉及大量个人数据，且方法论上难以设对照 |
| 为商业产品做效果背书 | 利益冲突 |
| 收集用户生辰做"研究" | 隐私风险，且无必要 |
| 建立个人命例数据库 | 即便匿名化，风险仍高 |
| 评价其他流派的"真假" | 超出能力，也非本项目的职责 |

## 六、如何评价我们的可信度

给你几个**可操作的检查点**：

### 检查 1：看有没有层级标注

如果一篇文章通篇没有区分"史实"与"传说"，**它的可信度就低**。

### 检查 2：看有没有版本信息

引用古籍却不写版本，说明作者可能**没见过原书**，只是转引。

### 检查 3：看有没有承认不确定

好的研究文本会明确说"这一点不清楚"。
如果什么都说得斩钉截铁，**反而可疑**。

### 检查 4：看有没有可复现的工具

本项目的工具你可以自己跑、自己改、自己验证。
如果一个说法只能"听我说"，那它不可验证。

### 检查 5：看我们对批评的反应

如果你指出我们的错误，我们**改了**，说明这个项目是认真的。
如果我们删评论、回避问题，那就不值得信任。

**欢迎你来检验第 5 条。**

## 七、工具的可验证性

`demo/tieban_open_tools.py` 的设计原则是**可审计**：

| 特性 | 好处 |
|---|---|
| 零依赖（仅标准库） | 你能看到全部代码，没有隐藏层 |
| 不到 400 行 | 你能在一小时内读完 |
| 26 项测试 | 你能自己验证行为 |
| 不使用网络 | 你能确认它不上传数据 |
| 明确的能力边界 | 不会假装能做它做不到的事 |

**你可以这样验证**：

```bash
cd demo
python -m unittest discover -s tests -v   # 跑测试
grep -i "import requests\|urllib\|socket" tieban_open_tools.py   # 检查网络调用
```

第二条命令应该**没有输出**。

## 九、方法论上的自我限制

诚实地说，本项目有几个**结构性局限**：

| 局限 | 影响 |
|---|---|
| 我们只有公开文献 | 看不到私藏抄本，可能遗漏关键材料 |
| 我们不是专业史学研究者 | 文献学功底有限，可能有误判 |
| 我们有商业利益 | 虽然努力保持客观，但立场不可能完全中立 |
| 我们的样本有限 | 只见过有限数量的公开转录本 |

**请把本项目当作"一个诚实的入门引导"，而不是"权威学术著作"。**

真正的学术研究，请查阅专业期刊与专著。
